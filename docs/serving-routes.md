# Serving a route: handlers, workers and HTTP servers

Unsworn checks every request against your API's rules, then hands it to
your code. Your code can receive it in two ways, and a project can use
both, route by route:

- **As a handler function.** Unsworn calls it with the validated request
  and sends back what it returns.
- **As an HTTP server.** Unsworn forwards the request, as HTTP, to an
  ordinary app built on a framework. Unsworn can start and supervise the
  app (an [HTTP runtime](http-runtime.md)), or forward to one you run
  yourself, at its address.

```toml
[[route]]                            # a handler function
path    = "/chat"
method  = "POST"
handler = "src/chat.py"

[runtimes.api]                       # an HTTP server Unsworn starts
command  = "bun run server.ts"
protocol = "http"

[[route]]
path  = "/invoices/{*rest}"
proxy = { runtime = "api" }

[[route]]                            # an HTTP server you run yourself
path  = "/legacy/{*rest}"
proxy = "http://old-api:8080"
```

## Handlers or an HTTP server

| | Handlers | HTTP server |
|---|---|---|
| You write | A function per endpoint | An app with its own router |
| Languages | TypeScript/JavaScript, Python, Go and Rust with an SDK; any other with a hand-written worker | Any language with an HTTP server |
| Routes are written | Once, in the config or as route files | In the config for the rules, and again in the app |
| Data input | Validated, and typed with [types generated](types.md) from the config | As sent in the URL and body |
| Calling [other handlers](functions.md) and [outbound services](outbound.md) through Unsworn | Yes (`ctx.call`, `ctx.fetch`) | Yes, as HTTP requests to a [local endpoint](http-runtime.md#calling-functions-and-outbound-services) |
| Runs on | Servers and containers; JS/TS handlers also at the edge and in serverless functions | Servers and containers |

The rules are the same either way: a route's `auth`, `require`, rate
limit, validation and `before` handlers pass before a handler is called
or a request is forwarded. An HTTP server is told who the caller is in the
[`Unsworn-Context`](config.md#who-the-caller-is-unsworn-context) header.

## Handlers: with an SDK, or a worker of your own

Handlers run in worker processes that Unsworn starts and talks to over a
[small protocol](protocol.md). The SDK is that protocol already written
for you.

| | SDK worker | Hand-written worker |
|---|---|---|
| Languages | TypeScript/JavaScript, Python, Go, Rust | Anything that can read and write lines of JSON on stdin and stdout |
| You write | Handler functions | Handler functions, plus the loop that reads requests and writes responses |
| A typo in a handler's name | Reported by `unsworn check --deep`, before any request | Found on the first request |
| Types from the config | Generated by `unsworn gen` | None |
| Streaming, cancellation, `ctx.call`, `ctx.fetch` | Built in | Available, but you send and match the protocol messages yourself |
| Several requests arriving at the same time | One worker process handles many of them | A simple loop handles one, so Unsworn runs more copies of the worker when requests have to wait |

A hand-written worker can be
[about a dozen lines](protocol.md#a-complete-worker-with-no-sdk), because
it only implements what its handlers use.
[`examples/raw-python`](../examples/raw-python) is one, and
[`examples/cobol`](../examples/cobol) is one in a language with no JSON
parser. Use an SDK when your language has one.

## Which function a reference finds

A handler reference names a file and, after `#`, a function:
`src/users.ts#getUser`. With no `#name`, as route files have, each SDK
looks for the file's default handler:

| Language | A reference with no `#name` finds |
|---|---|
| TypeScript and JavaScript | The default export, or an export named `handler` |
| Python | A function named `handler`, or one named `default` |
| Go | A function named `Handler`, or the only handler registered from that file |
| Rust | The function registered for the file with `Handlers::add_ref` |

`unsworn check` confirms that the file exists. `unsworn check --deep` and
`unsworn dev` start the workers and report a reference no function
answers to.
